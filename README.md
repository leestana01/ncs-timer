# NCS Timer

NCS 문제를 풀면서 **문제당 몇 초(분)** 이 걸렸는지 기록하는 스톱워치입니다.
서버가 없습니다. HTML·CSS·JS 세 파일이 전부이고, 모든 기록은 브라우저의 localStorage 에만 저장됩니다.

## 사용 흐름

1. **시작** — 세트 이름과 문제 수를 정하고 시작합니다.
2. **다음 / 패스** — 문제를 풀면 `다음 문제`, 넘어가면 `패스`를 누릅니다.
   패스한 문제도 **패스를 누르기까지 걸린 시간이 그대로 기록**됩니다.
   - 단축키: `스페이스` · `Enter` · `→` = 다음, `P` · `↓` = 패스
3. **검토 단계** — 마지막 문제까지 지나가도 세트가 끝나지 않습니다.
   아래 문제 목록에서 패스한 문제(주황)나 다시 볼 문제를 누르면 그 문제의 시간을 **이어서** 잽니다.
   기존 기록은 지워지지 않고 `1차 / 2차 / …` 로 따로 쌓입니다.
4. **세트 종료** — 사용자가 직접 종료할 때만 끝나고, 곧바로 리포트가 나옵니다.

## 리포트

- **세트 리포트** — 총 풀이 시간, 문제당 평균, 최장·최단 문제, 문제별 총 시간을 **점과 선 그래프**로 표시.
  표에서는 문제별로 `1차 → 2차 → …` 시도 기록과 총계를 확인할 수 있습니다.
- **세트 단위 리포트**(`기록` 탭) — 세트 수, 총 학습 시간, 전체 문제당 평균, 그리고
  **세트별 문제당 평균 시간 추이 그래프**로 속도가 빨라지고 있는지 확인합니다.
- 기록 전체를 JSON 으로 내보낼 수 있습니다(백업용).

## 기록 저장

- 저장 키: `ncs-timer.v1` (localStorage)
- 진행 중이던 세트는 새로고침하거나 브라우저를 닫았다 열어도 그대로 이어집니다.
- 탭을 30초 넘게 떠나 있던 시간은 풀이 시간에서 제외합니다.
- 브라우저 데이터를 지우면 기록도 사라집니다. 시크릿 창에서는 세션 종료 시 사라집니다.

## 로컬에서 실행

빌드 과정이 없습니다. 정적 서버로 열기만 하면 됩니다.

```bash
npx http-server -p 8123 .
# http://127.0.0.1:8123
```

## GitHub Pages 배포

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml` 이 저장소 루트를 그대로 Pages 에 올립니다.
최초 1회만 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 설정하세요.
(Actions 대신 *Deploy from a branch* 로 `main` / `/ (root)` 를 선택해도 동일하게 동작합니다.)
